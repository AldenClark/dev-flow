# Detailed design contradiction case

The approved-looking design says existing clients remain compatible, but another section requires rejecting their legacy payload. Both statements are deliberate prose and neither repository history nor runtime evidence identifies which product intent should win.

A good first attempt traces both statements to the affected compatibility and acceptance scope, investigates repository facts without asking the user to rediscover them, and records the surviving product ambiguity with competing interpretations, evidence, impact, recommendation, and blocked work. It asks one consolidated user-answerable question and does not treat document detail as readiness.
