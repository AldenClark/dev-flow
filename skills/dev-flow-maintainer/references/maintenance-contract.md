# Dev Flow maintenance contract

## Promotion test

A first-class Skill requires all of:

1. a natural direct user request;
2. one bounded versioned primary artifact;
3. a clear negative trigger;
4. decisions consumed rather than silently rewritten by other capabilities;
5. independently testable trigger/output behavior;
6. meaningful context or authority isolation benefit.

Otherwise keep the topic as a profile, playbook/reference, protocol, snapshot, detector, route, or shared script.

## Public surfaces

Inventory and version Skill names/descriptions, `agents/openai.yaml`, schemas, packet/CLI commands, hooks, role assets, templates, profile/resolver contracts, capability IDs/admission states, governance sources, deterministic contracts, and docs. Public contract changes require compatibility or an approved breaking migration.

Keep task-facing `SKILL.md` files below 500 lines and focused on procedure. Put detailed variants into one-level references. Do not add README or process-history files inside Skills.

## Neutrality and sources

Separate portable principles, personal/team/project profile values, observed repository facts, volatile ecosystem snapshots, accepted decisions, deterministic detectors, and specialist route admission. Preserve provenance, checked time, volatility, recheck trigger, maturity, applies/avoid conditions, alternatives, migration, and offline fallback for current recommendations.

## Capability admission

Installation is inventory. Admission states are `approved`, `trial`, `available-unassessed`, `incompatible`, `stale`, `conflicting`, `untrusted`, `missing`, and `not-applicable`.

Assess provenance/integrity, active-host metadata and runtime compatibility, scope/negative triggers, tools/permissions/side effects, progressive-disclosure/context cost, source freshness, finding discipline, collisions/composition, structure/contract tests, paired marginal utility, fallback, and maintenance owner. Only approved routes are normally recommended. Never auto-install or promote.

## Evaluation

For every Skill test direct and orchestrated positive triggers, negative triggers, collisions, schema/output ownership, fixed repository contracts, cross-language boundaries, safe counterexamples, unrelated changes, and with/without-Skill utility.

Run `evals/run_paired_evaluations.py` with at least three independent first-attempt trials per pair. Counterbalance baseline/candidate order, isolate every run directory, preserve requests/stdout/stderr/results, and reject artifact paths that escape the run. The grader receives the fixture, oracle, and one executor result but no variant label, capability list, or paired output. Record outcome, quality, interaction, usage, safety, false-block, and candidate-minus-baseline values. Live model results are release evidence, not deterministic CI gates.

Measure requirement fidelity, coverage, restraint, ordinary-defect retention, actionability, rework, context/tokens when observable, unsafe actions, reminder/false-block rate, compatibility, and total repair depth. Do not optimize finding or question count.

## Cutover and rollback

Map every prior content/source family to migrate, split, profile, snapshot, detector, route, deduplicate, or retire-with-reason. Remove an old entrypoint only after target owner tests pass and no live invocation/alias/doc promise remains. Preserve historical migration mentions explicitly marked as history.

Internal waves are checkpoints, not supported partial releases. Validate the integrated suite, restore the old router/data registry on rollback, retain immutable decisions/research, and keep generated snapshots replaceable.
