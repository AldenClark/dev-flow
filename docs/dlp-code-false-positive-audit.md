日期：2026-10-26。基线：`2187955`。状态：本地源码修复与相关验证完成；用户已授权作为 2.1.2 提交、正式发布并更新本地安装，执行事实见[发布记录](workstreams/dev-flow-2.1.2/progress.md)。

用户先要求修复 Android 测试夹具中的变量引用误报，并保持真实凭据拦截；随后要求扩大为代码场景的深度审计。本轮按语法与数据边界排查，不把相同机制在不同语言中的重复样例计为不同缺陷，也不宣称穷尽任意代码或运行时行为。

## 原始事件与因果边界

原始 Android 子任务三次写入均被已安装 Dev Flow 的本地 `PreToolUse` Hook 拒绝。命中片段都是命名参数右侧的 `replacement)`：赋值正则把右括号算进值，引用识别因此失败，长度与字符种类判断又把它升级为 `secret_assignment`。这是代码引用误报；改用内存仓库没有改变待写源码，因此仍触发相同检测。

仓库与已安装 2.1.1 的原检测器在诊断时逐字节相同。修复仅在当前仓库；正在运行的已安装 Hook 没有被更新。原 Android 写入或测试未由本轮代为重试。

## 已验证并处理的代码场景

下表中的 `<field>` 代表敏感参数名，例如 `password`；示例中的值均为代码引用或本地合成测试值。

| 场景族 | 具体覆盖 | 原结果与原因 | 当前处置与反向保护 |
|---|---|---|---|
| 调用末尾的变量 | `copy(<field> = replacement)`、Swift 参数标签、嵌套调用、数组包裹、后续 fluent 调用 | `)`、`]` 等被误读为凭据的一部分 | 只在有界命名参数语境识别完整引用，不截断原始值或脱敏范围；普通无引号带这些字符的值仍检查 |
| 引用名称与前缀 | snake_case、camelCase 加数字、Rust `&`/`*`/`r#`、Swift 隐式成员及闭包参数 | 装饰后的引用不符合旧匹配 | 按有限引用语法识别；混合大小写数字的凭据控制继续拦截 |
| 引用下标与后缀 | 标识符下标、可选值 `?`、非空断言 `!!` | 被视为含特殊字符的长值 | 命名参数内的引用放行；结构化 JSON 字符串仍按字面量检测 |
| 参数布局 | 首参数、后续参数、换行参数、闭合多个括号 | 旧规则对排版及末尾分隔符敏感 | 使用同一引用判定，不添加语言、文件名或测试目录的整体豁免 |
| URL 插值 | Python `f`/`fr`/`rf` 与同一字符串的 `.format`、转换符、常用格式说明符、数字下标、多行及前导文字，JS 模板、shell 环境变量；明文及 base64 表示 | 纯引用及其常见格式变体被识别为 URL 密码 | 仅完整引用且属于对应格式字符串时豁免；真实字面量及引用/字面量混合继续检测和脱敏 |
| 格式表达式的归属 | 普通 URL 后的无关 `.format`、下一行的格式字符串 | 修复草稿曾可能借用后续表达式豁免当前 URL | 匹配限制在当前字符串边界；独立复核反例已转成原生回归并关闭 |
| 凭据字面量的包装 | 普通/三引号、借用字符串、包装函数位置/命名/后续参数、空格、注释，Python raw/bytes/格式字符串、Rust raw 字符串内部引号 | 部分前缀、三引号、命名参数及注释边界原先跳过实际字面量 | 检查包装表达式的字面量，再考虑引用；注释标点不终止调用检查，注释中的疑似凭据仍检查；纯格式引用不当作凭据 |
| 解释器源码参数 | Python `-c` 中的成员访问和 import，源码末尾为 `.key`；脚本、模块、首个源码目标确定后的参数 | 整段代码曾被当成文件名，后续普通参数又可能被误当源码 | 源码不按文件名后缀归类；执行目标确定后不重新识别 `-c`，实际文件参数仍检查 |
| 搜索与日志模式 | `rg` 的首个模式、`-e`/`--regexp`，`git log --grep` | 搜索词如 `record.key` 被当成凭据文件 | 只识别已知模式参数；实际文件、模式文件 `-f`、glob、重定向及未知选项保留保守检查 |
| 嵌套 shell | `sh`/`bash`/`zsh`/`dash` 的 `-c`/`-lc` | 内层相对敏感路径可能因外层后缀不匹配而漏检 | 有界递归检查内层命令；深度、整体文本及单个词法单元上限保持 fail-closed |
| 环境配置文件 | `.env.production.local` 等多段后缀 | 旧规则只接受一段后缀，可能漏检 | 多段后缀纳入检测；仅完整 `.env.example`/`.env.sample`/`.env.template` 等既有安全模板继续豁免 |
| 实际敏感操作 | 读取密钥文件、搜索敏感文件、Git 敏感文件参数、重定向、Python 显式打开敏感文件 | 应当阻止的保护场景 | 对应原生控制继续拦截，不给解释器、搜索工具或测试夹具整体白名单 |

源码所有者为 [检测器](../skills/company-data-security/scripts/data_security.py)，新增的黑盒语法/拦截控制在 [代码误报回归](../evals/test_dlp_code_false_positives.py)。原有 [引擎审计](../evals/test_dlp_engine_audit.py)、[Hook 审计](../evals/test_dlp_hook_audit.py)及[数据安全测试](../evals/test_data_security.py)继续拥有既有保护契约。

## 已排查且有意保留的检测

| 场景 | 排查结论 | 保留理由 |
|---|---|---|
| JSON 中看似变量的字符串 | 仍作为字面量检查 | JSON 字符串没有代码变量引用语义，不能沿用源码豁免 |
| Authorization 后的裸词 | 仍作为凭据候选 | 与合法 bearer 值无法仅凭外观区分；不扩大赋值引用规则到鉴权头 |
| 代码或示例中的邮箱 | 仍可能触发 C3 脱敏 | 出现在代码、公用域名或测试中本身不能证明没有个人信息，不添加域名或源码整体白名单 |
| 类似电话号码的分组数字 | 维持既有规则 | 某些诊断数字与手机号外观相同；日期、时间戳、版本及普通计数的现有非误报控制保留 |
| PEM 标记与实际密钥形状 | 仅标记/转义源码保持原有放行，完整或截断密钥体继续拦截 | 不以能否成功解析密钥证明它不敏感，也不放宽重排后的密钥体保护 |
| 已脱敏标签及文档链接 | 维持现有精确语法 | 只豁免既定完整标签与窄文档引用，邻接真实凭据及不完整标签仍检查 |
| 大型工具结果被整体替换 | 保留现有上限 | 敏感结果不能因过长而原样返回；误报会放大其影响，但不应为此取消原结果隔离 |
| 未知工具、shell 选项、通用 `.key` 文本 | 无法确定角色时继续保守 | 同一字符串可能是成员访问、模式或真实文件名，需要调用边界提供角色；不将静态猜测视为实际文件操作证据 |
