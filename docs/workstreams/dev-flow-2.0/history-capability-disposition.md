# Dev Flow historical capability disposition

This audit traces the useful capability line from `v0.2.0` through the unpublished 1.1.3 source and the 2.0 beta worktree. It distinguishes preserved engineering capability from retired default ceremony. The local and remote published tag inventory ends at `v1.1.2`; 1.1.3 exists only as later source history and changelog material.

## What was intentionally not restored

- packet creation or activation for ordinary 2.0 work;
- lifecycle transition gates, checkpoint digests, evidence ledgers, change-set bindings, approval receipts, leases, or per-phase mandatory files;
- process Hooks that classify every command or infer completion;
- load-all specialist/method behavior, mandatory delegation, or dual blue/red reports;
- universal compatibility matrices, install/rollback rehearsals, or model trials for unrelated changes;
- effectiveness, productivity, developer-ranking, or composite workflow scores.

## 2.0 breaking boundary

Dev Flow 2.0 provides no compatibility contract for legacy packet, knowledge, method-record, evaluation, installation, or release state. Residual implementations are unsupported internal debt and never reactivate in new work. Users retain historical repository files at their own discretion; removal or extraction requires no 2.0 compatibility ceremony.
